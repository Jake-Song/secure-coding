# 최신 AI 해킹 기법과 방어

**자료 확인일 2026년 11월 26일.** 생성형 AI에서 가드레일을 우회하는 기법부터, 문서 검색과 외부 도구가 연결된 서비스에서 권한 경계가 무너지는 경우까지 다룬다. 예시는 AI 보안 과정의 메모 요약 도우미를 기준으로 한다. [AI 서비스 보안 과정](curriculum.md)

## Jailbreak와 프롬프트 인젝션

- **Jailbreak(탈옥)**는 모델이나 서비스의 안전 가드레일을 우회해 정책상 제한되는 응답을 얻으려는 시도다. 확인할 결과는 정책 위반 응답이 실제로 사용자에게 전달됐는지다.
- **프롬프트 인젝션**은 모델이 입력에 포함된 텍스트 등을 지시로 받아들여, 앱이나 사용자가 정한 작업에서 벗어나게 하는 문제다. **직접 인젝션**은 사용자가 보낸 요청에서, **간접 인젝션**은 모델이 읽는 문서·메일·웹페이지·도구 응답 등에서 시작한다. Jailbreak에 직접 인젝션이 쓰일 수 있고, 간접 인젝션은 사용자에게 보이는 답변 외에 도구 호출에도 영향을 줄 수 있다. [OWASP 프롬프트 인젝션](https://genai.owasp.org/llm2026/llm012026-prompt-injection/)

예를 들어 메모 요약 도우미가 검색한 문서의 내용을 앱의 지시로 받아들여 요약과 무관한 작업을 제안할 수 있다. 이때 **모델이 작업을 제안했는지**, **앱이 실행했는지**, **데이터가 외부에 전달됐는지**를 각각 확인해야 실제 영향을 판단할 수 있다.

## 어떤 형태로 나타나나

| 유형 | 원리 | 방어에서 확인할 점 |
|---|---|---|
| 다중 턴 jailbreak | 앞선 대화가 누적되면서 이후 응답에 대한 안전 판정이 달라지는 유형이다. | 한 번의 질문과 여러 턴의 대화를 모두 평가한다. 정상 대화의 오차단도 함께 집계한다. |
| 입력 표현에 따른 jailbreak | 의미가 같은 요청도 언어, 표현, 입력 형식에 따라 안전 판정이 일관되지 않을 수 있다. | 지원 언어와 입력 형식별로 정책 판정이 일관적인지 확인한다. |
| 간접·멀티모달 인젝션 | 문서·웹페이지·도구 응답이나 이미지 속 텍스트가 모델의 입력에 합쳐지면서 작업을 바꿀 수 있다. | 첨부 파일과 OCR 결과에도 원본의 출처와 신뢰 수준을 유지한다. 도구 권한은 앱에서 별도로 검사한다. |
| RAG 검색 데이터 오염과 문서 권한 오류 | 변경된 문서가 검색되면 답변의 근거가 오염될 수 있다. 사용자별 검색 범위가 빠지면 권한 없는 문서가 모델 문맥에 포함될 수 있다. | 등록·변경 권한과 문서 버전을 관리한다. 모델에 넘기기 전에 사용자별 문서 권한을 적용하고 캐시에도 같은 범위를 유지한다. |
| 숨은 문맥 노출 | 시스템 메시지, 내부 메타데이터, 도구 반환값 등 사용자에게 보이지 않아야 할 정보가 생성 응답에 나타날 수 있다. | 비밀값을 모델 문맥에 넣지 않는다. 모델에 전달할 필드와 사용자에게 표시할 필드를 각각 제한한다. |
| 에이전트 도구 오용과 과도한 권한 | 정상 도구라도 에이전트에 부여된 권한이 넓으면 원래 작업과 무관한 조회·공유·변경이 실행될 수 있다. | 서버에서 사용자·대상·행동을 검증한다. 외부 전송과 변경은 승인 화면에 대상과 범위를 보여 주고 실행 시 다시 확인한다. |
| 메모리·문맥 오염 | 잘못된 정보가 에이전트의 장기 메모리에 저장되면 이후 세션의 판단과 도구 호출에도 영향을 준다. | 쓰기 권한과 출처를 확인하고, 사용자별로 메모리를 분리한다. 문제가 생긴 항목을 식별해 삭제하거나 이전 버전으로 되돌릴 수 있게 한다. |
| 도구·모델 공급망 오염 | 모델, 패키지, 커넥터 또는 도구 정의가 승인 없이 바뀌면 모델이 보는 정보와 실행 가능한 기능이 함께 달라질 수 있다. | 승인된 버전과 출처를 기록한다. 업데이트에서 도구 정의와 권한 변경을 검토하고 기존 테스트를 다시 실행한다. |
| 모델 출력의 위험한 처리 | 모델이 생성한 문자열을 앱이 HTML이나 실행 가능한 명령처럼 처리하면 텍스트 응답이 브라우저나 시스템의 동작으로 이어질 수 있다. | 출력 형식과 허용 값을 코드에서 검사한다. 화면에서는 텍스트로 렌더링하고, 허용된 작업은 정해진 인터페이스를 통해 실행한다. |

모델이 생성한 답변의 안전성, 서버의 권한 집행, 문서의 무결성은 각각 다른 검사 대상이다. 예를 들어 응답에서 비밀을 가려도, 타인 문서가 이미 외부 모델로 전송됐다면 검색 단계의 기밀성 문제는 남는다. ## 메모 요약 도우미 방어를 검증하는 방법

합성 문서 `A1`은 Alice 소유, `B1`은 Bob 소유로 설정한다. 모델의 결과는 고정된 모의 응답으로 주고, 앱이 내리는 결정을 기록한다.

| 검사 | 기대 결과 | 확인할 근거 |
|---|---|---|
| Alice가 자기 회의 메모를 요약 | `A1`이 검색되고 요약이 표시된다. | 검색 문서 ID, 표시 결과 |
| 같은 검색어가 Bob의 메모에 등장 | Alice의 모델 문맥에는 `B1`이 들어가지 않는다. | 모델 호출 직전에 선택한 문서 ID |
| 모의 응답이 `B1`을 출처로 제시 | 출력 검사가 답변 표시를 보류한다. | 출처 검사 결과, 최종 표시 여부 |
| 모의 도구 요청이 승인 없이 공유를 제안 | 앱이 공유를 실행하지 않는다. | 승인 상태, 실제 전송 기록 |
| 사용자 권한이 회수된 뒤 같은 검색을 다시 실행 | 이전 검색 결과나 캐시에서도 문서가 반환되지 않는다. | 현재 권한 판정, 검색 및 캐시 결과 |

모의 응답은 앱의 권한 검사와 후속 처리를 검증하는 데 쓴다. 모델 가드레일을 평가할 때는 모델·정책 버전, 정책 위반 응답이 표시된 비율, 정상 응답이 차단된 비율을 함께 기록한다. 요약 원문이나 인증 토큰은 평가 로그에 남기지 않는다.
