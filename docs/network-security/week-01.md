## IP 주소와 포트

클라이언트가 `127.0.0.1:9000`에 연결하면 IP 주소는 **이 컴퓨터**를, TCP 포트는 **이 컴퓨터 안에서 연결을 받는 소켓**을 가리킵니다. 서버 프로세스가 소켓을 열고 주소와 포트를 지정한 뒤 연결을 기다립니다. TCP와 UDP는 모두 IP 위에서 동작하며 같은 포트 번호라도 각각 관리합니다.

CIDR 표기 `192.0.2.0/24`의 `/24`는 IPv4 주소의 앞 24비트가 같은 범위를 뜻합니다. `192.0.2.25`는 이 범위에 들어가고 `192.0.3.25`는 다른 접두사를 가집니다. 운영체제는 목적지에 맞는 경로를 선택해 사용할 인터페이스와 다음 홉을 결정합니다.

| 개념 | 하는 일 |
|---|---|
| DHCP | 호스트에 IP 주소, 게이트웨이 같은 네트워크 설정을 제공합니다. |
| ARP와 IPv6 이웃 탐색 | 같은 링크에서 다음 홉에 도달하는 데 필요한 링크 계층 정보를 알아냅니다. IPv4는 ARP를, IPv6는 Neighbor Discovery를 사용합니다. |
| ICMP | 목적지 도달 불가 같은 네트워크 제어 메시지를 전달합니다. |
| NAT | 경계를 통과하는 패킷의 IP 주소를 변환하고, 구성에 따라 포트도 변환합니다. |

## 실제 연결을 관찰하기

터미널 A에서 에코 서버를 켭니다. `127.0.0.1:9000에서 한 연결을 기다립니다.`가 나타나면 터미널 B에서 연결하기 전에 소켓과 경로를 조회합니다. [TCP 서버 코드](../../examples/tcp_server.py)

```bash
# 터미널 A
python3 examples/tcp_server.py
```

```bash
# 터미널 B
ss -ltnp 'sport = :9000'
ip -br address
ip route
ip route get 127.0.0.1
python3 examples/tcp_client.py '네트워크 실습'
```

`ss`에서 `LISTEN` 상태와 `127.0.0.1:9000`을 찾으세요. 프로세스 정보가 보이면 Python의 PID도 기록합니다. 경로 조회에서는 로컬 경로와 `lo`를 확인하세요. 클라이언트는 `네트워크 실습`을 그대로 돌려받고 서버는 한 연결을 처리한 뒤 종료합니다. 외부 목적지에서 사용할 기본 경로는 `ip route` 출력의 `default` 행에서 확인할 수 있습니다. [TCP 클라이언트 코드](../../examples/tcp_client.py)

**확인 문제.** 같은 컴퓨터에서 웹 앱과 에코 서버를 함께 실행하면 IP가 같아도 각각 어떻게 찾나요? `127.0.0.1` 연결에서 기본 게이트웨이는 어떤 역할을 하나요?

**제출물.** 클라이언트에서 서버까지의 연결 그림과 `IP 주소·인터페이스·프로토콜·포트·프로세스` 관찰표를 작성하세요. 로컬 연결과 기본 경로의 차이를 한 문장으로 설명하세요.
