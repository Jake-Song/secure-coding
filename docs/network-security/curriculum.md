# 네트워크 보안 12주 커리큘럼

**주 6~8시간, Linux·Python 입문자 기준**입니다. 연결과 패킷을 이해한 뒤 프로토콜 입력 검증, TLS, 메시지 인증, 접근 정책, 로그 탐지를 학습합니다. 최종 목표는 작은 통신 서비스를 분석하고, 잘못된 입력·권한·신뢰 설정에 대한 방어를 구현해 재검증하는 것입니다.

웹 보안과 역엔지니어링 과정에서 독립적으로 시작할 수 있습니다. 웹 과정에는 HTTP·인증·접근 제어로, 역엔지니어링 과정에는 바이너리 프로토콜·파일 형식 분석으로 연결됩니다.

## 선수 지식과 준비

- 터미널에서 파일을 찾고 권한을 확인하는 일이 낯설면 [Bandit 시작하기](../bandit.md)를 먼저 진행합니다. 준비 기간은 별도로 1~2주를 잡습니다.
- Python의 함수, `bytes`·`str`, 예외 처리, `with` 문법을 사용할 수 있다고 가정합니다. 처음이면 1~2주를 추가합니다.
- 기본 환경은 Linux 또는 WSL2, Python 3.10 이상입니다. 네트워크 예제는 Python 표준 라이브러리만 사용합니다. TLS 실습에는 OpenSSL CLI 1.1.1 이상이 추가로 필요합니다.
- 실제 통신은 `127.0.0.1`의 임시 포트에서 이루어집니다. 데모는 필요한 서버를 직접 시작하고 정해진 연결을 처리한 뒤 종료합니다. 관리자 권한·외부 서버·추가 Python 패키지는 필요하지 않습니다.
- Wireshark·tcpdump·실제 방화벽은 선택 확장입니다. 기본 실습을 실행하기 위해 설치할 필요는 없습니다.

저장소 루트에서 확인하고 실행합니다. 웹 앱을 먼저 켤 필요는 없습니다.

```bash
python3 --version
openssl version
python3 -m examples.network_security --help
python3 -m examples.network_security all
```

OpenSSL이 없다면 TLS를 제외한 실습을 개별 실행할 수 있습니다. 검증 기록에는 **실제 소켓**, **메모리 단위 테스트**, **합성 데이터 분석** 중 어떤 방식이었는지 적으세요.

## 1~4주차 프로토콜을 바이트로 읽기

1주차에는 [TCP 에코 실습](week-01.md)을 두 터미널에서 실행합니다. 서버가 기다리는 동안 `ss -ltn`으로 `127.0.0.1:9000`을 찾습니다. Linux에서 도구가 있다면 `ip -br address`, `ip route`로 인터페이스와 기본 경로를 관찰합니다. loopback 실행이 기본 게이트웨이·실제 NIC를 거치지 않는다는 점을 정리합니다.

ARP/이웃 탐색, DHCP, ICMP, NAT는 주소·경로와 함께 개념을 학습합니다. 제공 코드는 해당 기능의 공격이나 실제 장비 설정을 수행하지 않습니다. IPv6의 주소·이웃 탐색은 IPv4와 비교하는 확장 주제입니다.

2주차에는 `framing.py`에서 4바이트 big-endian 길이와 payload를 추적합니다. 3바이트 단위 쓰기를 사용하더라도 OS가 수신을 같은 크기로 나눌 의무는 없습니다. 테스트의 `FragmentedReader`는 한 번에 1바이트만 반환해 부분 읽기를 확실하게 재현합니다.

3주차에는 생성한 PCAP에서 헤더 길이를 직접 계산합니다. 이 파일에는 DNS 질의·응답 2개만 있습니다. TCP handshake가 없다는 것이 정상이며, 실제 TCP handshake·재전송·TLS 레코드 관찰은 자신의 loopback 통신을 캡처하는 선택 과제로 남깁니다.

4주차에는 DNS wire 형식의 헤더·질문·압축 이름 포인터를 살펴봅니다. ID만 맞는 응답, 질문까지 맞는 응답, 지정한 서버 endpoint에서 온 응답의 차이를 설명합니다. 이 조건을 만족해도 DNSSEC 검증을 수행한 것은 아닙니다. 제공 파서는 단일 `IN A` 질의·응답의 제한된 형식만 지원합니다.

## 5~8주차 통신과 접근의 신뢰 경계

5주차에는 연결 대상 IP와 인증서에서 검증할 이름을 구분합니다. 코드의 TCP 목적지는 `127.0.0.1`, TLS의 `server_hostname`은 `localhost`입니다. CA를 신뢰해도 인증서 이름이 다르면 실패해야 합니다. 인증서 생성은 임시 디렉터리에서 이루어지며 시스템 신뢰 저장소를 변경하지 않습니다.

6주차에는 HMAC이 데이터를 숨기지 않는다는 점부터 확인합니다. 같은 메시지와 MAC을 다시 보내면 MAC-only 구현은 재수락합니다. nonce·시간 창을 검사하는 구현은 동일 요청의 재사용과 오래된 요청을 거부합니다. 이 예제의 HMAC은 공유 키 인증이며 공개 키 디지털 서명과는 다릅니다.

7주차에는 클라이언트→웹 TCP/443, 웹→DB TCP/5432만 허용하는 모델을 읽습니다. 클라이언트→DB, TCP/22, UDP/443은 거부됩니다. UDP/443 거부가 QUIC까지 막을 수 있다는 정책적 영향을 토론합니다. 실제 방화벽의 규칙 순서·상태 추적·리턴 트래픽·NAT 적용 위치는 이 모델에 없습니다.

8주차에는 Alice 키로 올바르게 인증한 요청도 Bob의 메모를 읽을 수 없어야 함을 확인합니다. 객체 소유권 검사는 MAC 검사 이후 서버가 수행합니다. 네트워크 위치, 메시지 작성자 인증, 객체 접근 권한은 서로 다른 판단입니다. [웹 보안의 객체 접근 제어](../web-security/week-04.md)와 비교합니다.

## 9~10주차 자원과 관찰

9주차에는 큰 payload를 실제로 보내기보다 4바이트 길이 헤더만으로 수신 측 상한 검사를 확인합니다. nonce 저장소가 가득 차면 기존 항목을 조용히 버려 재전송을 허용하는 대신 새 요청을 거부하는 동작을 분석합니다.

소켓 timeout은 각 blocking 작업의 대기 시간 제한입니다. 메시지 전체의 절대 마감 시간·운영용 동시 연결 제한·사용자별 rate limit을 제공하지 않습니다. 시간 창 기반 HMAC은 시계 동기화가 필요하고, 메모리 nonce 저장소는 재시작·여러 서버 간에 공유되지 않습니다. 이런 조건을 운영 시스템에서 어떻게 처리할지 설계 과제로 작성합니다.

10주차에는 source·destination 쌍별 10초 창에서 서로 다른 거부 포트 4개, 인증 실패 3회를 탐지합니다. 임계치에 처음 도달할 때 경보를 내고, 조건이 해제된 뒤 다시 도달하면 재경보합니다. 같은 포트 반복, 서로 다른 호스트, 20초 간격 활동을 비교합니다. 임계치 경보는 공격 확정 판정이 아닙니다.

## 11~12주차 최종 프로젝트

제공된 모듈을 조합해 **메모 조회용 로컬 TLS 서비스**를 구현합니다. 완성된 통합 서버는 과제이며, TLS·인증·프레이밍 함수와 테스트를 재사용합니다. 운영용 프로토콜을 새로 설계하는 과제로 확대하지 않습니다.

처리 순서:

```text
loopback 연결 → TLS handshake → 길이 제한 프레임 읽기
             → JSON 스키마 → HMAC → 시간·nonce → 메모 소유권 → 응답
```

검증할 항목:

- 올바른 CA·이름·키·소유권을 가진 요청은 성공한다.
- 미신뢰 CA와 잘못된 호스트명은 애플리케이션 요청 전에 거부된다.
- 변조된 내용·재전송·오래된 요청·타인 메모·초과 길이를 각각 거부한다.
- 정상 오류 처리 후에도 다음 정상 요청이 성공한다.
- 로그에 원문 키·MAC·메모 본문을 남기지 않는다.
- 실제 연결의 peer 주소와 클라이언트가 보낸 주소 문자열을 혼동하지 않는다. 정책 모델의 주소를 실제 연결의 신뢰 정보로 사용하지 않는다.

제출 보고서는 환경·커밋·명령, 통신 형식, 신뢰 경계, 예상/실제 결과, 수정 근거, 미검증 항목을 포함합니다. 코드 이해·명세 25%, 정상 동작 25%, 거부·회귀 검증 35%, 재현성과 기록 15%로 평가합니다.

## 제공 코드와 범위

| 실습 | 실제 수행 | 포함하지 않는 내용 |
|---|---|---|
| TCP 프레이밍 | 실제 로컬 TCP, 다중 프레임, 상한·잘림 검사 | TCP 스택 구현, 패킷 분할 보장 |
| DNS·PCAP | 실제 로컬 UDP DNS, 합성 PCAP 생성 | 재귀 리졸버, 캐시 오염, DNSSEC, EDNS·CNAME·TCP fallback |
| TLS | 실제 TLS 채널, 임시 CA/서버 인증서, CA·호스트명 실패 | 공개 CA 발급, mTLS, 인증서 폐기·자동 갱신 |
| HMAC·재전송·인가 | 실제 TCP 위 요청·응답과 검증 비교 | 암호화, 키 배포·회전, 분산 nonce 저장소 |
| 접근 정책 | IP·포트·프로토콜에 대한 오프라인 기본 거부 모델 | OS 방화벽 변경, 실제 망 분리·NAT·상태 추적 |
