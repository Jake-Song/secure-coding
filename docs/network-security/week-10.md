## 로그 여러 줄에서 한 경보 만들기

JSONL은 한 줄에 JSON 객체 하나를 담는 형식입니다. 예제는 `time`, `source`, `destination`, `port`, `event`를 읽습니다. 분석기는 출발지와 목적지의 **쌍**마다 현재 시각에서 10초 전까지의 이벤트를 봅니다. 경계 시각도 집계에 들어갑니다. [합성 로그](../../examples/network_security/events.jsonl)

한 창에서 서로 다른 거부 포트가 4개 이상이면 `many_denied_ports`, 인증 실패가 3건 이상이면 `repeated_auth_failures`를 기록합니다. 처음 임계치에 도달할 때 경보를 만들고, 이후 해당 쌍의 이벤트를 평가할 때 조건이 해제됐음을 확인하면 다시 경보를 낼 수 있습니다. [탐지기 코드](../../examples/network_security/detection.py)

## 두 경보의 근거 찾아보기

```bash
python3 -m examples.network_security detection
python3 -m unittest tests.test_network_policy.DetectionTests -v
```

출력의 요약은 `10 events, 2 alerts`입니다. 각 경보를 다음 근거와 연결하세요.

| 경보 시각 | 출발지 → 목적지 | 근거 이벤트 |
|---:|---|---|
| 4 | `192.0.2.50` → `198.51.100.10` | 시각 1~4의 거부 포트 `22`, `23`, `445`, `3389` |
| 7 | `192.0.2.60` → `198.51.100.10` | 시각 5~7의 `auth_failure` 3건 |

샘플의 정상 요청, 같은 포트가 반복되는 단위 테스트, 시간 간격이 큰 이벤트의 집계 결과를 비교하세요. 운영 로그에서 NAT 뒤에 있는 여러 사용자가 한 IP로 보이거나, 필요한 로그가 센서에 도착하지 않는 경우도 생각해 보세요. 경보는 조사할 신호이고, 다른 로그와 대조해 원인과 영향을 판단합니다.

**확인 문제.** 같은 출발지가 다른 목적지에 남긴 이벤트가 이 규칙에서 어떻게 집계되나요? 같은 포트가 반복되는 경우와 여러 포트가 거부된 경우는 어떤 값이 달라지나요?

**제출물.** 두 경보에 해당하는 원본 이벤트, 적용된 시간 창, 오탐과 미탐 가능성을 설명할 사례를 기록하세요.
