# 7주차 네트워크 분리와 접근 정책

[이전 6주차](week-06.md) · [12주 커리큘럼](curriculum.md) · [다음 8주차](week-08.md)

## 필요한 방향만 열기

이 모델에는 클라이언트 구역, 웹 서버, DB 서버가 있습니다. 정책은 출발지·목적지·전송 프로토콜·목적지 포트 네 조건이 모두 맞을 때만 요청 흐름을 허용합니다. 허용 규칙과 일치하지 않으면 기본 동작은 거부입니다.

| 출발지 | 목적지 | 프로토콜과 포트 | 결과 |
|---|---|---|---|
| 클라이언트 `192.0.2.0/24` | 웹 `198.51.100.10` | TCP/443 | 허용 |
| 웹 `198.51.100.10` | DB `203.0.113.20` | TCP/5432 | 허용 |
| 클라이언트 | DB | TCP/5432 | 거부 |
| 클라이언트 | 웹 | TCP/22 | 거부 |
| 클라이언트 | 웹 | UDP/443 | 거부 |

## 오프라인에서 정책 검증하기

```bash
python3 -m examples.network_security policy
python3 -m unittest tests.test_network_policy.PolicyTests -v
```

출력의 `ALLOW` 두 행과 `DENY` 세 행을 표와 대조하세요. `policy.py`의 첫 번째 규칙에서 `/24`는 클라이언트 구역, `/32`는 목적지 웹 서버 주소 하나를 지정합니다. 같은 목적지·같은 포트에서 프로토콜만 TCP에서 UDP로 바뀌면 규칙과 일치하지 않으므로, 이 정책을 실제로 적용한다면 UDP/443을 쓰는 QUIC도 영향을 받습니다. [모델 코드](../../examples/network_security/policy.py)

이 코드는 문서 전용 IP 주소로 요청 방향만 계산합니다. 실제 상태 기반 방화벽에서는 응답 트래픽, 연결 상태, 규칙 순서, NAT 적용 위치도 별도로 검토합니다. 애플리케이션은 접속이 허용된 뒤에도 요청한 사용자의 인증과 객체 권한을 판단합니다.

**확인 문제.** 웹 서버가 DB에 연결할 수 있다는 규칙은 클라이언트의 DB 직접 접속에 어떤 영향을 주나요? DB에서 웹으로 응답이 돌아오는 조건을 표현하려면 모델에 어떤 정보가 더 필요하나요?

**제출물.** 허용 행렬에 역방향 요청과 잘못된 포트 사례를 더하고, 각 결과를 만든 규칙 또는 기본 거부 조건을 설명하세요.
