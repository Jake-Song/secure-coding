# 6주차 SQL 인젝션과 파라미터 바인딩

[이전 5주차](week-05.md) · [웹 보안 커리큘럼](curriculum.md) · [다음 7주차](week-07.md)

SQLite는 SQL 문자열을 쿼리 문법으로 해석합니다. 사용자 입력을 그 문자열에 이어 붙이면 입력까지 문법에 영향을 줄 수 있습니다. `safe_search`는 `WHERE name LIKE ?`의 `?` 자리에 검색값을 별도 인자로 전달합니다. 검색값이 달라져도 SQL 문장의 구조는 유지됩니다. [검색 코드](../../app.py)

정상 문자열 `Note`와 따옴표가 들어 있는 일반 텍스트 `O'Reilly`를 방어 경로에서 검색해 보세요. `--data-urlencode`는 셸에서 전달한 검색값을 URL 쿼리로 인코딩합니다.

```bash
curl --noproxy '*' -sS -G --data-urlencode 'q=Note' http://127.0.0.1:5000/safe/search
curl --noproxy '*' -sS -G --data-urlencode "q=O'Reilly" http://127.0.0.1:5000/safe/search
```

첫 요청은 `Notebook` 한 건, 두 번째는 `[]`를 반환합니다. 따옴표가 검색값으로 처리됐고 해당 상품은 없다는 뜻입니다. `LIKE`의 `%`와 `_`는 검색 패턴 기능을 갖습니다. 검색 정책에서 이 문자들을 일반 문자로 다뤄야 한다면 패턴 처리도 따로 설계해야 합니다.

**확인 문제.** `q`가 바뀔 때 SQL 문자열과 바인딩 값 중 어느 쪽이 바뀌나요? URL 인코딩은 이 과정의 어느 시점에 쓰이나요?
