# Chapter 10 코드 리뷰와 관찰

[이전 Chapter 9](chapter-09.md) · [웹 보안 커리큘럼](curriculum.md) · [다음 Chapter 11](chapter-11.md)

기능을 하나 선택하고 **입력 출처 → 해석 위치 → 필요한 권한 → 실패 시 상태와 로그** 순서로 따라가세요. `app.py`의 비밀번호 검사, 쿠키 플래그, 요청 크기 제한, 거부 로그를 읽고 설정이 적용되는 위치를 찾습니다. [앱 코드](../../app.py)

| 표현 | 목적 | 예 |
|---|---|---|
| 인코딩 | 전달하거나 저장할 수 있는 형태로 데이터를 바꿉니다. | Base64 |
| 암호화 | 키를 가진 쪽이 내용을 복원할 수 있게 보호합니다. | TLS 통신의 암호화 |
| 해시 | 입력으로부터 고정된 길이의 요약값을 얻습니다. | 파일 무결성 확인 |
| 비밀번호 해시 | 솔트와 비용 설정을 사용해 비밀번호 추측에 드는 비용을 높입니다. | 앱의 `check_password_hash`가 검증하는 저장값 |

아래 명령으로 환경에 설치된 패키지 버전과 의존성 충돌 유무를 확인하세요. `pip check`는 의존성 호환성을 확인합니다. 알려진 취약점 점검에서는 패키지의 실제 버전과 배포사의 보안 공지를 대조합니다.

```bash
python -m pip list
python -m pip check
```

`uv`로 준비한 가상환경에서는 `uv pip list`와 `uv pip check`를 실행하세요. 충돌이 없으면 각각 패키지 목록과 의존성 점검을 통과했다는 결과를 볼 수 있습니다.

`require_csrf`의 거부 로그는 메서드와 경로를 남깁니다. 로그에 있는 값만으로 어느 기능에서 거부됐는지 읽어 보세요. 브라우저 기록이나 보고서를 공유할 때는 비밀번호, 세션 쿠키, 토큰도 가립니다.

**확인 문제.** 토큰의 실제 값 없이도 CSRF 거부를 조사하려면 어떤 로그 항목이 도움이 되나요?
