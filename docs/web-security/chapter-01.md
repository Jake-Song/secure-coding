# Chapter 1 네트워크

[웹 보안 커리큘럼](curriculum.md) · [다음 Chapter 2](chapter-02.md)

`http://127.0.0.1:5000/session`에서 `127.0.0.1`은 이 컴퓨터의 주소, `5000`은 앱이 듣는 포트, `/session`은 HTTP 요청 경로입니다. `example.com`처럼 이름으로 접속할 때는 DNS가 IP 주소를 찾는 데 쓰입니다. 이 예시 URL에는 IP 주소가 직접 적혀 있습니다.

| 개념 | 요청 흐름에서 하는 일 |
|---|---|
| TCP | 데이터를 순서가 있는 바이트 스트림으로 전달합니다. |
| UDP | 데이터그램 단위로 보냅니다. 도착 여부와 순서는 달라질 수 있습니다. |
| HTTP | 요청의 메서드·경로·헤더·본문과 응답의 상태 코드·헤더·본문을 정의합니다. |
| TLS | 데이터를 암호화하고 변조를 검사합니다. 일반적인 HTTPS에서는 서버 인증서도 검증합니다. |

보내는 쪽에서 TCP로 `HELLO`와 `WORLD`를 따로 보내도, 받는 앱은 `HELLOWORLD`를 한 번에 읽거나 `HEL`과 `LOWORLD`로 나눠 읽을 수 있습니다. 앱이 줄바꿈을 메시지 경계로 정했다면 `HELLO\nWORLD\n`에서 두 메시지를 복원할 수 있습니다. UDP에서는 두 데이터그램이 도착하면 각각 읽습니다.

HTTPS에서 HTTP/1.1이나 HTTP/2를 쓰면 일반적으로 `HTTP → TLS → TCP → IP` 순서로 데이터가 전달됩니다. HTTP/3는 TLS를 통합한 QUIC과 UDP를 사용합니다. TCP와 UDP 모두 IP 위에서 동작하며, 인터넷 프로토콜 묶음인 TCP/IP에 속합니다.

**실습 A.** 각각 다른 터미널에서 아래 명령을 실행하세요. A가 대기 메시지를 표시한 뒤 B에서 실행하면, B에 `안녕하세요`가 출력되고 A도 종료됩니다.

```bash
# 터미널 A
python examples/tcp_server.py
```

```bash
# 터미널 B
python examples/tcp_client.py '안녕하세요'
```

클라이언트의 `shutdown(SHUT_WR)`는 보낼 데이터가 끝났다는 신호입니다. 서버는 수신 EOF를 확인하고 연결을 닫습니다. 클라이언트는 그동안 되돌아온 데이터를 읽고 자기 쪽 수신 EOF까지 기다립니다. 실행 흐름은 [TCP 클라이언트 코드](../../examples/tcp_client.py)에서 확인할 수 있습니다.

**실습 B.** 앱을 실행한 상태에서 아래 명령을 실행하세요. `200 OK`, JSON을 나타내는 `Content-Type`, 로그인 전의 `"username":null`을 찾아보세요. 쿠키와 `csrf` 값은 기록에서 가립니다.

```bash
curl --noproxy '*' -i http://127.0.0.1:5000/session
```
