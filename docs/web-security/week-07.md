# 7주차 XSS와 출력 문맥

[이전 6주차](week-06.md) · [12주 커리큘럼](curriculum.md) · [다음 8주차](week-08.md)

브라우저가 입력을 페이지 구조나 실행 가능한 코드로 해석하는 지점에 XSS 위험이 생깁니다. 반사형은 현재 요청의 값이 응답에 포함되고, 저장형은 저장한 값이 이후 화면에 포함됩니다. DOM 기반 XSS는 클라이언트 JavaScript가 받은 데이터를 위험한 DOM API에 전달할 때 생길 수 있습니다.

아래 명령은 방어 경로에서 일반 문장부호가 HTML로 어떻게 표현되는지 확인합니다.

```bash
curl --noproxy '*' -sS -G --data-urlencode 'name=연습 < 확인 & 기록' http://127.0.0.1:5000/safe/greet
```

HTML 응답에는 `연습 &lt; 확인 &amp; 기록`이 있고, 브라우저가 표시하는 문장에는 `<`와 `&`가 보입니다. `safe_greet`는 Jinja 템플릿 변수에 값을 넣어 HTML 텍스트 문맥의 자동 이스케이프를 적용합니다. DOM에서 일반 텍스트를 넣는다면 `textContent`를 사용할 수 있습니다. URL 값에는 허용할 스킴을 검증하고, JavaScript에 데이터를 전달할 때는 해당 문맥에 맞는 직렬화를 사용합니다. [인사 화면 코드](../../app.py)

**확인 문제.** 같은 입력이라도 HTML 텍스트, 링크 URL, JavaScript 문자열에서 검사할 조건이 왜 달라지나요?

**제출물.** 한 입력의 원래 값·응답 HTML·화면 텍스트를 나란히 적고, 반사형·저장형·DOM 기반 예시 각각에서 데이터의 출처와 해석 위치를 그림으로 표시하세요.
