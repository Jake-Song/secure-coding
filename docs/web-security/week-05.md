# 5주차 인증과 객체 접근 제어

[이전 4주차](week-04.md) · [웹 보안 커리큘럼](curriculum.md) · [다음 6주차](week-06.md)

**인증**은 현재 요청이 누구의 것인지 확인하는 과정이고, **인가**는 그 사용자가 특정 행동을 할 수 있는지 판단하는 과정입니다. IDOR는 사용자가 지정한 객체 ID를 서버가 처리할 때 해당 객체에 대한 권한 검사가 빠져 생깁니다. 같은 역할의 다른 사용자 데이터는 수평 권한의 문제, 일반 사용자가 관리자 기능을 쓰는 경우는 수직 권한의 문제입니다.

`/safe/notes/<note_id>`에서 아래 결과를 예상한 뒤, 각 계정으로 본인 메모를 읽고 방어 경로의 반환 코드와 테스트를 확인하세요. 사용자별 관찰은 로그아웃 후 다시 로그인하거나, 서로 다른 테스트 클라이언트를 사용합니다.

| 요청한 사용자 | 메모 1 | 메모 2 | 없는 메모 |
|---|---:|---:|---:|
| 비로그인 | 401 | 401 | 401 |
| Alice | 200 | 404 | 404 |
| Bob | 404 | 200 | 404 |

이 앱의 `safe_note`는 SQL에서 `id`와 `owner_id`를 함께 제한합니다. 조회 결과가 없으면 `404`를 반환하므로 다른 사용자에게 메모의 존재 여부도 드러나지 않습니다. `@login_required`의 `401`은 객체를 조회하기 전에 반환됩니다. [앱 코드](../../app.py)

**확인 문제.** 메모 URL을 추측하기 어려운 값으로 바꿔도 서버 쿼리에 어떤 조건이 필요할까요?

**제출물.** 접근 행렬을 채우고, 각 `200`에서 본 메모 ID와 `401`·`404`가 갈리는 조건을 설명하세요.
